📖 Arti error Supabase yang sering muncul

error.code / pesanartinya
invalid_credentialsEmail/password salah — ATAU user-nya memang belum ada. Supabase sengaja nggak bedain demi keamanan.
email_not_confirmedAkun ada tapi email belum diverifikasi → selesaikan OTP dulu (tab Kode OTP).
user_already_exists / email_existsEmail udah terdaftar. Catatan: signUp kadang "sukses" tapi identities kosong = juga tanda email udah terdaftar.
weak_password / validation_failedPassword nggak lolos policy project (panjang/huruf besar/angka/simbol).
over_email_send_rate_limitKebanyakan minta email (free tier ±2-4/jam!). Tunggu, atau set custom SMTP.
otp_expired / Token has expired or is invalidKode kadaluarsa, udah kepake, ATAU type verifyOtp-nya salah (signup vs recovery vs email).
refresh_token_not_found / invalidSession lokal basi (token udah dirotasi di tempat lain). Logout → login ulang. Cek tab Storage.
Failed to fetch (exception, bukan error Supabase)Request nggak nyampe: URL project salah, internet, CORS, adblock, atau file://.
429Rate limit. Lihat body response buat detailnya.

🔐 RLS (Row Level Security) — penyebab #1 "login sukses tapi data kosong"

  • RLS itu filter diam-diam: SELECT yang nggak diizinin policy hasilnya array kosong, BUKAN error. Dashboard jadi kelihatan "kosong" padahal query "sukses".
  • 42501 = operasi ditolak policy (sering kena pas INSERT/UPDATE).
  • PGRST116 = pakai .single() tapi 0 baris → profil belum dibuat (trigger signup jalan?) atau kefilter RLS.
  • Contoh policy minimal buat tabel profil (SQL editor Supabase):
-- Schema lo (Clauder/schema.sql) SUDAH punya policy-nya:
--   user_profiles_select_own_or_admin  (select: auth.uid() = user_id / admin)
--   user_profiles_update_own_or_admin
--   app_request_select_own_or_admin / app_request_insert_own
-- Kalau data kosong padahal login sukses, cek policy itu beneran
-- ke-apply di project Supabase lo:
select tablename, policyname from pg_policies
 where schemaname = 'public';
-- Kalau kosong → schema.sql belum pernah dijalanin penuh di project ini.
  • Habis login, request data harus bawa JWT role authenticated — cek di tab Network bagian "Token JWT terdeteksi". Kalau masih anon: session nggak kebawa (client beda instance / beda storage key).
